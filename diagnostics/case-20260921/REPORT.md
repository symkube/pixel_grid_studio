# 网格识别诊断：2026-09-21

## 已保存的材料

- `manual.pixel.json`：用户下载的项目文件的完整副本，包含图像、手动横纵网格、取色设置。没有改写用户网格。
- `source.png`：从项目内嵌图像提取的 1254 × 1254 PNG。它是浏览器使用的图像副本，不是导入前 JPEG 的原始文件字节。
- `manual-grid.png` / `automatic-grid.png`：手动及原算法网格叠加图。
- `comparison.png`：原算法与手动网格对照。
- `analysis.json` / `edge-projections.csv`：数值结果及原始边缘投影。
- `experimental-grid.png` / `experiment-comparison.png` / `experiment.json`：离线联合优化实验。

## 结论

这张图的主要问题是横向边界的全局拟合方式，不是没有找到大致间距。横纵两个方向都估计为 29 像素，纵向与手动结果非常接近，横向两端特别是右半部偏差很大。

现有实现是“整数周期自相关 → 单一相位 → 每条线独立在窄窗口中找峰”。它没有实现最初讨论的全局序列优化，也没有约束实际相邻网格的间距变化。

## 本图可复现的原因

1. 横向算法选中周期 29、相位 20，理想位置为 `20 + k * 29`。
2. 每条线只搜索理想位置前后 `floor(29 * 0.24) = 6` 像素。
3. 手动横向间距大多约 29 像素，但存在 23–34 像素的变化。这些局部差异积累后，正确位置会越出固定窗口。
4. 例如手动边界 x=903 对应明显边缘，投影强度约 24.46；算法在 x=890 处的强度仅约 0.26。x=903 已经在该窗口之外，所以无法选中。
5. 现有异常标记只判断最终位置偏离“理想位置”是否超过周期的 15%。选中 x=890 这种几乎没有边缘的位置反而不会触发异常。它没有检查线上的证据是否充分，也没有寻找网格未解释的强边缘。

`core.js` 的关键位置：51 行起为周期估计；70 行起为相位选择；76 行起为独立局部搜索；87 行为异常标记；91 行为可信度返回。

## 其他已证实的问题

- **整数间距导致倍周期误识别。** 对长度 1024 的完全干净合成边缘，实际间距 9.5、10.5、20.5 分别被识别为 19、21、41，漏掉约一半边界。这是单独的缺陷，不应当当作本图的直接原因。
- **可信度使用了错误的对象。** 返回的是所有候选周期的最高相关值，不一定是实际选中的周期。实际间距 12.8 时，选中的 13 像素周期相关值约 0.778，却因为另一个周期得到 1.0 而报告 100%。即使选中周期的相关值很高，也不能等价为网格正确概率。
- **上限约束会排除可表示的正确网格。** 1024 像素、8 像素间距恰为 128 格，但 `ceil(n / 127)` 将最小周期限制为 9，实验识别成 16。超过产品格数上限时也应提示，不能静默改成倍周期。
- **输入控件有额外的编辑问题。** 修改任何一个水平或垂直间距/偏移输入，都会重新生成两轴网格，可能清除另一轴已经拖好的边界；偏移又只由首条线和中位间距反推，对非均匀网格并不可靠。见 `app.js` 37–40、178–181 行。
- **退化边缘格。** 保存的网格为 44 列、43 行，其中最后一列是 1253.5–1254，仅宽 0.5 像素。这可能是将多余边界推到图边缘的结果。界面缺少直接删除/合并边界的操作，应补充提示及合并能力。取色还会把宽度钳制到至少 1 像素，使该列成为重复取样，导出时却仍占一个完整像素。

## 离线优化实验

只读取原图和现有算法估出的周期，格数从 `round(1254 / 29) = 43` 推断，未用手动网格指导拟合。手动网格仅用于事后评估。

对边缘投影轻度平滑并压缩极强峰的权重，用动态规划共同选择所有边界：奖励边缘证据，惩罚相邻间距偏离估计周期。没有把边界锁在固定相位的小窗口中，因此局部位移可以沿序列传递。

指标为每条手动内部边界到最近预测内部边界的距离。排除最后的 0.5 像素退化列。手动网格是参考，不是已确认的绝对真值；最近距离指标也不能单独衡量所有错误。

| 指标 | 原算法 | 离线实验 |
| --- | ---: | ---: |
| 横向预测内部边界数 | 43 | 42 |
| 横向参考内部边界数 | 42 | 42 |
| 横向平均最近距离 | 5.83 px | 0.86 px |
| 横向最远最近距离 | 14 px | 4 px |
| 横向 2 px 内匹配比例 | 47.6% | 92.9% |
| 纵向平均最近距离 | 0.14 px | 0.26 px |
| 纵向 2 px 内匹配比例 | 100% | 100% |

横向仍有三个位置与手动结果相差超过 2 像素：840→844、1019→1022、1162→1165。纵向平均距离略有上升，说明不宜直接宣称新方法全面优于原方法。

实验固定使用估计格数并要求首尾覆盖整图，还没有处理裁切造成的半格、弱证据区、多种尺度等情况。它验证了优化方向，尚不应直接替换正式算法。

## 建议的实施顺序

1. 用动态规划替换固定相位下的独立寻峰，比较多个格数/相位候选，允许裁切边缘存在不完整格子。结合间距偏差及相邻间距的平滑约束，允许缓慢漂移而抑制突然挤压。
2. 将周期搜索从整数扩展到小数，用峰间距、多周期候选及漏掉的强边缘共同排除倍周期。上限作为明确的产品提示，避免参与错误的周期选择。
3. 分别输出周期可信度、逐线边缘支持度、多个候选之间的歧义；检查无法被当前网格解释的强边缘，避免“错得整齐却没有提示”。
4. 分区域统计边缘证据，减轻局部复杂纹理或轮廓对全图的支配，并识别需要局部网格处理的区域。
5. 手动固定的网格线作为后续优化的约束；单轴调整不改另一轴；补充增删/合并网格线和极窄格提示。
6. 扩展回归样本：本图及人工参考、非整数间距、累计漂移、裁切边缘、稀疏边缘、倍周期、JPEG 噪声及达到格数上限的输入。原测试主要是整齐的合成网格，不足以验证这些场景。

本次仅添加诊断资料和离线实验脚本，未修改网页算法，也未操作浏览器里的手动编辑状态。
